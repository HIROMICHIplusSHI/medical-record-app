## 1. Phase 4の位置づけ

### 1.1 背景

Phase 3ではカルテ管理のコア機能を実装しましたが、以下の課題が明らかになりました:

- **ナビゲーション問題**: ヘッダーがないため、ページ間の移動が困難
- **ブラウザ確認の負担**: 各機能を個別URLで確認する必要があり、開発効率が低下
- **ユーザー体験**: 統一されたUIがなく、アプリとしての一体感が欠如

### 1.2 Phase 4の目的

Phase 4では、**実用的なアプリケーションとしての完成度を高める**ことを目指します:

1. **統一されたナビゲーション**: 全画面で共通のヘッダー実装
2. **iPad最適化**: メインペルソナ（iPad使用のアートメイク施術者）向けの最適化
3. **レスポンシブ対応**: スマートフォンでの使用も考慮
4. **ユーザビリティ向上**: 直感的な操作性の実現

## 3. 開発方針

### 3.1 設計原則

1. **段階的実装**: 小さな単位でPRを作成し、レビュー・マージを繰り返す
2. **テスト駆動**: Systemテストで動作を確認
3. **デザインシステム準拠**: `docs/08_screen_design.md` の仕様に従う
4. **iPad優先**: メインペルソナ向けに最適化し、スマートフォンは補完的対応

### 3.2 ワークフロー

```
feature/p4-XX-XXXX ブランチ作成
    ↓
開発・テスト
    ↓
PR作成（Draft）
    ↓
セルフレビュー・CI確認
    ↓
Ready for Review
    ↓
レビュー・修正
    ↓
main へマージ
```

### 3.3 品質基準

| 項目 | 基準 |
|------|------|
| **テストカバレッジ** | 80%以上維持 |
| **RuboCop** | 違反 0件 |
| **System Test** | 主要機能の動作確認 |
| **レスポンシブ対応** | iPad (768px以上)、スマホ (375px以上) |
| **アクセシビリティ** | 基本的なキーボード操作対応 |

### 5.1 技術的リスク

| リスク | 発生確率 | 影響度 | 対策 |
|--------|---------|--------|------|
